# Getting Started

How to run, stop and use the robot stack.

## Components

| Component | Where it runs | What it does |
|---|---|---|
| Robot (`firmware/esp32_robot_mqtt`) | ESP32 on the robot | Executes `robot/command`, publishes `robot/response` and `robot/telemetry` |
| Remote control | Second ESP32 (schematics in local `fotos/`, not versioned) | Reads joysticks/buttons, publishes to `robot/command` |
| ESP32-CAM | On the robot | Serves the camera as MJPEG (`http://<cam-ip>:81/stream`) |
| Camera stream server (`camera_stream/`) | Laptop | Sole client of the ESP32-CAM, re-serves the video on port 8000 |
| Node-RED dashboard (Docker) | Laptop | Phone HUD: camera, remote-control direction, sensors |
| Mosquitto (Docker) | Laptop | Local broker on 1883/9001 (currently unused, see note) |

> **MQTT broker:** the dashboard and firmware use the public broker
> `broker.hivemq.com:1883`. The local Mosquitto container is started but no
> flow uses it.

## Prerequisites

- Docker Desktop running.
- [`uv`](https://docs.astral.sh/uv/) for the camera server (it installs
  Python 3.13 if missing).
- Laptop, phone and ESP32 boards on the same Wi-Fi network.

## 1. Start the dashboard (Docker)

From the project root:

```bash
docker compose up -d --build   # build and start Node-RED + Mosquitto
docker compose ps              # check both containers are running
docker compose logs -f nodered # follow Node-RED logs (Ctrl+C to exit)
```

- Dashboard: <http://localhost:1880/ui>
- Standalone HUD page: <http://localhost:1880/robot>
- Node-RED editor: <http://localhost:1880>

## 2. Start the camera stream server

```bash
cd camera_stream
uv sync   # first time only: creates .venv from pyproject.toml + uv.lock

# ESP32-CAM
uv run stream_server.py --source http://<cam-ip>:81/stream
# Laptop webcam (for testing)
uv run stream_server.py --source 0
# Synthetic test pattern (no camera needed)
uv run stream_server.py --source test
```

### Choosing the source

| `--source` | Camera |
|---|---|
| `http://<cam-ip>:81/stream` | ESP32-CAM on the robot (final setup) |
| `0` | Laptop built-in webcam (`1`, `2`… for other connected cameras) |
| `test` | Synthetic pattern generated by the server, no real camera |

If the webcam does not open, close any other app using it (Teams, Zoom,
Windows Camera) or try the next index.

### Where to see the video

| What | URL |
|---|---|
| Live stream | <http://localhost:8000/raw.mjpg> |
| Single frame | <http://localhost:8000/snapshot.jpg> |
| Status (fps, connected) | <http://localhost:8000/health> |
| Robot page (video included) | <http://localhost:1880/robot> |
| Dashboard (video included) | <http://localhost:1880/ui> |

From the phone replace `localhost` with the laptop LAN IP (see section 3).

Stop the server with `Ctrl+C` in its terminal. More options:
`camera_stream/README.md`.

## 3. Use the dashboard from the phone

1. Find the laptop LAN IP: `ipconfig` (IPv4 address, e.g. `192.168.1.50`).
2. On the phone open `http://<laptop-ip>:1880/ui`.
3. In the Node-RED editor, set the `hud-camera-base-url` inject node to
   `http://<laptop-ip>:8000` and deploy, so the phone can load the video.
4. If the phone cannot connect, allow ports 1880 and 8000 in the Windows
   firewall.

Alternative view: `http://<laptop-ip>:1880/robot` is a standalone read-only
page with the same data (it polls `/robot/status`). It loads the video from
`http://<host it was opened from>:8000` automatically, so step 3 is not needed
for it. Override with `?cam=http://<ip>:8000`.

The HUD shows:

- **Cámara**: live stream and camera server status.
- **Control remoto**: direction and speed received on `robot/command`, and the
  robot state from `robot/response`.
- **Sensores**: ultrasonic distance, gas (shows "Sin datos" until the sensor
  publishes `{"sensor":"gas", ...}` on `robot/telemetry`) and an alert banner.

## 4. Power on the hardware

1. Robot ESP32: flash `firmware/esp32_robot_mqtt` (Wi-Fi credentials in
   `secrets.h`, not versioned).
2. ESP32-CAM: note its IP from the serial monitor.
3. Remote control: switch on; it publishes to `robot/command`.

## Stop everything

```bash
# Camera server: Ctrl+C in its terminal
docker compose stop    # stop containers (keeps them)
docker compose down    # stop and remove containers
```
